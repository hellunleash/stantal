Your tests pass. Your types check.
The model still gets it wrong.

When the thing calling your API is a language model, the descriptions are the contract. Delete a sentence of guidance and you have shipped a breaking change with no type signature. Nothing in your toolchain is looking at it.

$npx stantal connect

No account. No signup. No API key. It runs on your machine and reports in about a second.

What we found

168

contract changes a model would read differently, across 487 releases of 22 popular agent packages.

145

of them had no structural signal at all. No type error, no semver bump, nothing to fail a build.

Twelve of the twenty-two packages carried at least one. Ten carried none — including both official reference servers. A tool that found problems everywhere would just be broken, so the zeroes matter as much as the number.

One of them, in full

list_commits, in Anthropic's own reference GitHub server:

description: "Get list of commits of a branch in a GitHub repository"

owner:   z.string()
repo:    z.string()
sha:     z.string().optional()      <- what goes here?
page:    z.number().optional()
perPage: z.number().optional()

Three optional inputs. None of them described. The description mentions none of them. A model has no way to know whether sha takes a commit hash or the branch name in the sentence above it. This compiles, ships, and passes every test.

What you get

An answer

Take this upgrade, or don't. One word, and the evidence under it.

A test you keep

Records what your dependency offers today. Fails the day an upgrade takes it away.

A fix

Puts the deleted sentence back, when no released version is clean.

A link

One page you can send to whoever shipped it.

Why there is no API key

Most tools like this need a model to work, so they need your key, so they need an account before you can see anything. We don't.

WhatNeeds a key
Reading a package's toolsno
Comparing two versionsno
Writing the testsno
Finding which release broke itno
Confirming a judgement callyours, if you want it

A model is one narrow, optional job here: answering yes or no about whether a sentence explains an input, and quoting the text it used. Rules do the rest. Set ANTHROPIC_API_KEY, OPENAI_API_KEY or GEMINI_API_KEY if you want that step — it is your key, your bill, and never ours.

If you ship an API

Run it against a release you haven't published yet. Nothing is out there, so there is nothing to defend.

npx stantal check ./ --against 1.4.0

You find out which of your changes will silently strand customers while it still costs minutes to fix, instead of a support thread six months later.

Or skip the setup

npx stantal <package> <from> <to>      # should I take this upgrade?
npx stantal pin <package>              # lock in what it does today
npx stantal history <package>          # which release broke it?

Every one of those works with nothing installed and nothing configured.
